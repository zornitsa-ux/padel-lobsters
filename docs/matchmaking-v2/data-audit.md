# P0.1 — Historical Data Audit

Generated by `scripts/mm-audit.mjs` (dev-only, committed; re-run with
`node scripts/mm-audit.mjs` against a running local stack) plus read-only
production SELECTs, 2026-07-09/10. Fed the calibration inputs for DESIGN §6
(`D`, `beta`, `G`, `N_ref`). See D-006 for the decision this produced.

## Verdict

**Yes for volume, not yet for correctness (at the time).** Combined,
`History.jsx` and production gave **290 real scored matches** across 8 events
(4 hardcoded + 4 completed production tournaments), consistent low-variance
point totals (median 7, range 3–14) — enough for a real `D`/`beta`/`G` fit and
Brier backtest against Glicko-2.

Two findings drove follow-up work:

1. **`N_ref` as written in DESIGN §4.1 was miscalibrated** — measured median
   `s1+s2` per match is **7**, not ≈24, identically on `History.jsx` (n=116)
   and production (n=174). The tournament-_total_ per-player figures (median
   21–22) line up with "≈24," so the design value was almost certainly
   anchored on the wrong unit. Resolved by D-006 (`N_ref` → 7).
2. **16 of 68 historical names (24%) were unlinked** in
   `public.player_aliases` — real coverage gap, not a seed artifact.
   `ratingsRecompute.js` (since deleted) dropped any match where any of the 4
   players lacked a resolvable alias, directly shrinking the usable
   `History.jsx` match count. Owner chose not to link them; D-010's fit
   proceeded on production matches only.
